它是怎么运作的

先认识两个词 —— 节点：帮你转发流量的服务器；订阅：一个网址，客户端（v2rayN / Clash）定期来这取最新节点列表。

① ChromeGo 的源 —— 作者把免费节点放在云端几个固定地址（显示为「源1、源2」）。当它们是快递柜：柜子地址不变，里面包裹会换——节点被封了就换一批新的，有时连协议都换。 所以每次拉到的都是「这一刻柜子里的货」，隔几天回来重拉才稳。这些柜子国内不用翻墙就能开，拉取不依赖代理。

② 外部公共源（「来源二」面板） —— 别的作者把免费节点打包放在 GitHub 上，面板拉下来、只挑对应的协议。TCP 系节点会挨个试连、连不通的扔掉（像打电话看接不接）；hy1/hy2 走 UDP 试连无效，直接收、交给客户端「自动选择」挑。 GitHub 国内直连打不开：填了「代理地址」就走代理，没填就借国内「搬运站」（镜像）拿。这些源不自动更新，点「立即更新」才拿一次。

③ 开代理软件 ≠ 开系统代理 —— 开软件 = 开了一个「中转站」（如 127.0.0.1:10808）；开系统代理 = 在 Windows 贴张「告示」，告诉浏览器该走哪个中转站，它自己不干活。 所以「软件开着、系统代理关着」时，浏览器直连、上不去外网，但面板这种自己知道地址的程序照样能递进中转站——面板只认你填的「代理地址」，不看那张告示。

博主推荐

博主用下来的体会，供参考——好节点靠的是「线路」，不是协议，也不是时段：

认线路，别认协议 —— 好用的往往是一批稳定节点（比如同一家机场的服务器）。碰到顺手的，记下它的名字或「家族」，下次直接找它，不用管它跑的是 trojan、hysteria 还是别的。

延迟只作参考 —— 延迟低 ≠ 好用。美国节点延迟高、但带宽足，照样比很多低延迟节点跑得爽；真正决定体验的是这条线路稳不稳、快不快。

感觉不好使了，先回面板点一次「立即更新」——免费节点寿命短，多半是过期了，不是协议、时段或你网络的问题。懒得手动挑，就交给客户端的「自动选择」。
